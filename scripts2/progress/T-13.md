# T-13 — Narrow screen: the honest explanation

**Issue:** #13  **Commit:** ef022c4  **Status:** shipped

## What shipped

`src/narrow.js`: `isNarrow()` and `renderNarrow(root)`. `main.js` now branches on the viewport
*before* it builds anything, so a phone gets the explanation and nothing else is constructed —
no `AudioContext`, no `BroadcastChannel`, no animation frame.

Copy and layout are the design file's mobile screen, with one correction: "Each **window** sings
one note", not "Each tab". `screenX` is per window, so the design's wording would have been a
lie.

## Decisions made

- **The check is the first statement in `main.js`,** not a branch inside the gate's callback.
  Anything later would have already built the engine. Whoever touches the entry point next must
  keep the narrow branch ahead of `renderGate`.
- **`(pointer: coarse)` OR `innerWidth < 760`.** Either alone is wrong: a narrow desktop window
  can still be dragged, and a tablet at 1280 px still cannot move a window. The test suite covers
  both halves, including a `hasTouch` context at desktop width.
- **The "builds nothing" test instruments the constructors in an `addInitScript`,** so the
  counters are installed before the page's own script runs. Asserting on `window.__tabchoir`
  being absent would not have been enough — the hook is only exposed on join, so it is absent on
  the gate too and the test would pass vacuously.
- **The copy promises nothing.** The test asserts the absence of "soon", "coming", "yet",
  "support", "rotate" and "landscape" as well as the presence of "desktop". It is a closed door
  with a note on it, not a waiting room.
- **This is the one screen that reuses `.eyebrow`** from the gate. Everything else has its own
  `.narrow-*` class, so restyling the gate cannot silently restyle this.

## Deliberately left

- **Resizing from wide to narrow after joining does nothing.** The check runs once, at load. A
  window that has already lent its voice keeps singing if it is dragged small, and a window that
  loaded narrow will not become playable if it is dragged wide without a reload. This is
  explicitly out of scope per the issue's last criterion. If it ever matters, the fix is a
  `matchMedia` change listener that disposes the voice and swaps the screen — but it is not
  obviously the right behaviour, since a person resizing a window mid-chord probably does not
  want to be ejected from the piece.
- **No `dispose()` is called on anything**, because on the narrow path nothing was ever built.
