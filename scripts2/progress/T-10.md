# T-10 — Overlay typography: title, role, frequency, voice count

**Issue:** #10  **Commit:** 4bf4e6e  **Status:** shipped

## What shipped

Build stage three complete. `src/overlay.js` renders the wordmark top left and a monospace
readout top right — role in amber, frequency to one decimal place, voice count in words — with
the hint and status line along the foot. All of it real DOM above the canvas.

## Decisions made

- **`renderOverlay(root)` returns an update function** rather than exposing elements. `main.js`
  calls it from `update()`, so the readout changes exactly when the chord does.
- **`pointer-events: none` on `.overlay`, `auto` on its direct children.** The criteria wanted
  both selectable text *and* a canvas that is not intercepted; this satisfies both, and the test
  proves it with `elementFromPoint` at the centre of the screen returning the canvas.
- **The role is capitalised in CSS, not in the data.** `textContent` stays `bass`, which is the
  vocabulary `CONTEXT.md` uses and what `toHaveText` sees; `innerText` renders `Bass`. A test
  that reads `innerText` has to be case-insensitive — one of mine was not, and that is the only
  thing that failed here.
- **The status line reads "window position sets pitch"**, from the design. **T-12** overrides it
  for a listener.
- **The hint element exists but is empty.** **T-11** owns its copy and its one-way state machine;
  the grid row is already reserved so that task is copy and behaviour only, no layout.
- **Frequency shows an em dash when there is no note**, which is the listener case. **T-12**
  refines the rest of the listener wording.

## Deliberately left

- **The hint says nothing.** **T-11**.
- **A listener still shows `listener` as a role and an em dash for pitch**, which is correct but
  not yet the plain-words treatment the piece owes it. **T-12**.
- **No reduced-motion handling on the overlay.** The hint's fade arrives with **T-11** and
  **T-14** makes it instant.
