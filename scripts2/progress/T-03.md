# T-03 — Presence: deterministic roster over BroadcastChannel

**Issue:** #3  **Commit:** 3c31792  **Status:** shipped

## What shipped

Build stage one from the brief. After the gesture, a window opens the `tab-choir-v1`
BroadcastChannel, beats every 500 ms, and renders the roster as a `<pre>` dump — rank, role,
`joinedAt`, id, and a `self` marker on its own row. Three windows opened by hand show identical,
identically ordered rosters; closing one removes it everywhere well inside a second.

`src/roster.js` is pure and holds the three functions that must be exactly right: `sortRoster`,
`assignRoles`, `stale`. `src/presence.js` holds everything impure — channel, heartbeat, prune,
farewell — and nothing else.

## Decisions made

- **The roster is derived, never agreed.** There is no election, no tie-break message, no
  "who is bass?" exchange. Only two message types exist, `hb` and `bye`, and a discipline test
  asserts that set stays exactly that size. If a later task needs windows to agree on something
  that cannot be derived, that is a design change and should be parked, not implemented.
- **A stranger's first heartbeat gets an immediate reply.** Without it a new window waits up to
  a full 500 ms beat to learn who else is singing. This is an announcement, not a negotiation —
  nobody is told their role — and it is bounded: only *fresh* peers trigger a reply, so there is
  no echo storm. The "late window" test pins this at under 400 ms.
- **`joinedAt` is `Date.now()`, `seen` is `performance.now()`.** They are never compared to each
  other. `joinedAt` is broadcast and must be comparable across windows; `seen` is local-only and
  must be monotonic, and `performance.now()` origins differ per page so it must never be sent.
- **The dump marks `self`.** Tests need to know which row is the local window, and it makes the
  hand-check legible. `tests/e2e/windows.js` exposes `selfId(page)` and `ownRole(page)` off the
  back of it. When T-08 replaces the dump, that helper's parsing goes with it — the e2e suite
  will need `window.__tabchoir` (T-05) as its replacement source of truth.
- **`tests/unit/discipline.test.js` reads `src/presence.js` as text.** It guards four rules a
  behavioural test cannot watch fail: beats come from `setInterval` not rAF, farewell is
  `pagehide` not `unload`, `3000` appears exactly once as a named `PRUNE_MS`, and the message
  vocabulary is exactly `hb` + `bye`. Deliberately implementation-coupled — each of these ships
  silently and only shows up as a voice going missing when a window is backgrounded.
- **Two timeout budgets in the e2e suite**, and the distinction matters. `SETTLE` (6000 ms) is
  for getting a fresh roster into a known state — setup, not the point. `DEPART` (3500 ms) is
  the acceptance criterion itself and does not get to be generous. Do not collapse them.
- **`joinChoir` returns a `dispose()`** that nobody calls yet. T-15 and the narrow-screen branch
  will want it.

## Deliberately left

- **No pitch.** The dump shows no frequency; `theory.js` does not exist. **T-04** owns it.
- **No audio.** Nothing constructs an `AudioContext`. **T-05** owns it.
- **`window.__tabchoir` still does not exist.** **T-05** introduces it; until then e2e assertions
  read the DOM.
- **Prune is only unit-tested**, via `stale()`. Exercising the real timer needs a window whose
  heartbeat stops without closing, which is the backgrounded-window scenario — **T-15** owns it.
  The e2e departure tests here all go through the `bye` path.
- **`.roster-dump` styling is six lines of scaffolding**, marked as such in `styles.css`.
  **T-08** deletes it.
