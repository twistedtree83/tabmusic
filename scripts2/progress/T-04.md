# T-04 — Pitch mapping: window position to a note in the role's octave

**Issue:** #4  **Commit:** 7decac4  **Status:** shipped

## What shipped

`src/theory.js`, pure: the D Dorian pitch-class set, the five role roots, `roleOctave`,
`normalisePosition`, `quantise`, `midiToHz` and `avoidTritone`. `src/frame.js`, the piece's
single animation frame loop. `main.js` now polls `window.screenX` from that loop, quantises to a
note in its role's octave, broadcasts the frequency, and shows `t`, degree, MIDI note and Hz in
the dump alongside every peer's pitch.

Dragging a window left and right walks it through seven notes; closing the window above drops
this one an octave onto the same degree.

## Decisions made

- **`roleOctave` filters, it does not offset.** `roleOctave(57)` is `[0,2,3,5,7,8,10]` from the
  root, not the D-Dorian `[0,2,3,5,7,9,10]`. The test named "is not the D-Dorian shape
  transposed — alto is the proof" exists solely to catch a future refactor that "simplifies" this
  into `root + DEGREES[i]`. If that test ever looks redundant, it is not.
- **Position is seeded at join, not on the first frame.** `t` used to sit at 0 until the rAF
  callback first ran, so a window opened on degree 0 and corrected a frame later. Harmless
  against a `<pre>` dump, audible once T-06 puts oscillators behind it. `lastX`/`t` are now
  initialised from `window.screenX` before `joinChoir` is called.
- **Two peer-layer bugs fixed here, both found by this task's tests:**
  1. A *known* peer's heartbeat did not republish, so a window learned a peer's pitch once and
     never again. Now it republishes whenever `hz` changes.
  2. `joinChoir` published synchronously during construction, which put the caller's
     `const choir = joinChoir(...)` in the temporal dead zone the moment the callback tried to
     call `setPitch`. The first publish is now `queueMicrotask`ed. **Do not make it synchronous
     again** — the failure is a silent `ReferenceError` and an empty dump.
- **`setPitch` is re-entrant by exactly one level** and terminates because `retune()` returns
  false once the pitch has settled. If a later task adds another `setPitch` caller, check that
  invariant still holds.
- **`tests/e2e/fixtures.js` is now the import site for `test` in every spec**, not
  `@playwright/test`. It fails a test if the page threw. Without it, an uncaught exception just
  stops the piece updating and every assertion waits out its timeout: the bug above cost a
  17-minute test run and produced no stack trace. Keep new specs importing from here.
- **`lendVoice` waits 5 s for `.roster-dump`,** not the 30 s test default, so a broken join
  fails fast.
- **Frame discipline is asserted in `tests/unit/discipline.test.js`**: `requestAnimationFrame`
  appears only in `frame.js`, `MOVE_PX` is named and used once, and `main.js` polls `screenX`
  rather than listening for an event that does not exist.
- **`quantise` assumes a singing role.** `ROLE_ROOTS.listener` is undefined and `quantise` would
  return `undefined` rather than throwing. The single call site guards on `role !== LISTENER`;
  an e2e test pins that a listener reports `midi=0`, `degree=-1`. If a second call site appears,
  guard it there too or push the guard into `theory.js`.

## Deliberately left

- **`avoidTritone` is written and fully unit-tested but not yet wired in.** It is only correct to
  apply when exactly two voices are sounding, and "sounding" does not mean anything until voices
  exist. **T-07** owns applying it.
- **No audio.** Nothing constructs an `AudioContext`; `hz` is a number in a `<pre>` dump.
  **T-05** and **T-06** own the sound.
- **No glide.** Pitch changes are instantaneous integers here. **T-06** owns the 250 ms
  portamento.
- **`frame.js` has no pause/resume.** **T-15** owns cancelling the loop on `visibilitychange`
  and will need to add those exports.
- Adjacent role octaves overlap by up to a fifth, so two voices can cross. Accepted in the PRD;
  the tritone rule covers the only interval that would actually clash.
