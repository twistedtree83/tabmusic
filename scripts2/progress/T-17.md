# T-17 — A way to add a voice from inside the piece

**Issue:** #17  **Commit:** 8f5dee3  **Status:** shipped

## What shipped

"Open another window" at the foot of the stage, above the status line, in the same
monospace-and-rule treatment as the gate's "Lend a voice". It opens a second window on the same
URL, offset from this one, which arrives at the gate and needs its own gesture.

## Decisions made

- **A window, not a tab, and the distinction is the whole point.** `window.open` returns a tab
  when given no features and a window when given them, so the difference is one argument. A tab
  shares its parent's `screenX`: it would take the next role and sing a different octave, but it
  could never be moved off its parent's degree. That is a voice you cannot play, and this piece
  is about playing them. The user confirmed the choice.
- **The new window is offset by 60 px** from the opener's `screenX`/`screenY` and sized to 80% of
  it, so it does not land exactly on top and can be seen to be a second window.
- **The control is on the stage only.** The gate has its own invitation and the narrow screen has
  nothing to offer; tests assert its absence in both.
- **A listener still gets it.** A window that cannot sing can still open windows.
- **The "it is a window" assertion reads the source**, because Playwright reports a popup and a
  tab identically. It pins the `window.open(…, '_blank', \`width=…\`)` shape, and a separate test
  intercepts `window.open` to check the offset arithmetic against the live `screenX`/`screenY`.

## A CSS bug this uncovered

The reduced-motion test failed with `transition-duration: 0.6s, 0.6s, 0.8s`. The
`@media (prefers-reduced-motion: reduce)` block was sitting *above* the rules it switches off,
and **a media query adds no specificity** — so `.another { transition: … }`, declared later, won.

`.join` and `.hint` were in the same block and had the same problem. `.hint`'s reduced-motion
test had been passing for the wrong reason: the JS sets the swap timeout to zero under the
preference, so both opacity writes land in one frame and the transition never gets a chance to
run. The declaration was doing nothing.

The block now sits last in the stylesheet, with a comment saying why. **Anything appended to
`styles.css` from here must go above it.**

## Deliberately left

- **No control to close a window from inside the piece.** Closing is what the window chrome is
  for, and `window.close()` only works on windows a script opened.
- **The opener does not track the windows it has opened.** It could offer to bring them forward;
  it would need a handle per window and a reason to hold it, and there is not one yet.
