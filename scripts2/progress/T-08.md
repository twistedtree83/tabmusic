# T-08 — Stage canvas: the local waveform

**Issue:** #8  **Commit:** 7f5a914  **Status:** shipped

## What shipped

`src/stage.js`: a full-viewport, DPR-scaled, resize-observed `<canvas>` drawing this window's
own voice from `analyser.getByteTimeDomainData` as one 1.5 px amber stroke, tapered to nothing
at both ends, opacity breathing over nine seconds. Background `#171715`.

The `<pre>` dump is deleted. `window.__tabchoir` is now the only window into the piece.

## Decisions made

- **`window.__tabchoir` absorbed everything the dump carried** — `roster`, `selfId`, `t`,
  `degree`, `midi` — and `tests/e2e/windows.js` now reads the hook instead of parsing text. The
  helper names (`readRoster`, `rosterSize`, `ownRole`, `selfId`, `readPosition`) are unchanged,
  so `presence.spec.js` and `pitch.spec.js` needed almost no edits. Roster rows lost their
  `self` flag; compare `row.id` against `selfId(page)` instead.
- **The freeze on the hook is shallow.** `roster` rows are mutable by a caller. Not worth the
  lines to deep-freeze; the "cannot be steered" test covers the scalars.
- **The engine now closes its `AudioContext` on `pagehide`.** This is a real bug fixed here, not
  a test accommodation: a browser allows only a handful of contexts at once, and nothing ever
  handed one back. Every test passed alone and six failed in aggregate. `pagehide` and not
  `visibilitychange` — a backgrounded window must keep singing. T-05's ledger flagged this as
  T-15's call; it came due early.
- **The transform is set in `resize()` only**, not per frame. Assigning `canvas.width` resets
  the context state, so the transform is re-applied exactly where it is lost.
- **Assertions read pixels.** `strokeAt(page, columns)` scans a column for the highest red value
  — amber `#b8873f` has a red of 184 against an ink background of 23 — and returns its vertical
  position. That is how "the line deforms", "it tapers at both ends" and "amber on ink" are
  tested without a screenshot comparison.
- **A backgrounded window's rAF is throttled, so a single pixel scan races the first paint.**
  The listener test opens six windows and must poll until the stroke appears. It passed alone
  and failed in the suite until it did.

## A wrong turn worth recording

Checked by hand in the embedded browser pane, the waveform appeared to occupy only the top-left
59% of the window. I diagnosed a stale cached box, added a per-frame `clientWidth` check to heal
it, and wrote a test for it.

**The test passed without the fix**, which was the tell. Scanning the actual canvas pixels showed
the stroke reaching x=2508 of 2560 at y=0.5 — the drawing was correct all along. The pane
reports an emulated `innerWidth` of 1280 while compositing at its real 756×474, so only the
top-left of a correct canvas was visible. The fix was reverted.

Two lessons for later tasks: **measure the canvas, do not trust a screenshot from an emulated
viewport**, and **a regression test that passes before the fix has not reproduced the bug.**
The property test it produced was kept, because "the stroke reaches both edges" is worth
asserting regardless.

## Deliberately left

- **No sibling rules.** **T-09** owns peers, the drift lerp and ghosts.
- **No typography.** **T-10** owns the overlay; the stage is currently wordless.
- **The rAF loop is never cancelled.** **T-15** owns `visibilitychange`.
- **`prefers-reduced-motion` is not honoured by the canvas.** The breathing opacity should
  probably stop under it. **T-14** owns that call.
