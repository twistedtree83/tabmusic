# T-07 — The chord: roster drives voices, re-voicing, listener silence

**Issue:** #7  **Commit:** f24ff02  **Status:** shipped

## What shipped

Build stage two from the brief: **an ugly page with correct sound.** The roster now drives real
voices. Two windows sing two registers; closing one drops the survivor an octave; a sixth window
listens in silence and starts singing the moment a singer leaves.

`chordPitch(t, role, otherHz)` in `theory.js` is the whole decision, and it is pure.

## Decisions made

- **The tritone rule needs no message.** Each window computes `chordPitch` against the pair
  `[my quantised note, the one other sounding voice's broadcast hz]`. Both windows see the same
  pair and both lift whichever note is higher, so they agree without negotiating. This keeps the
  "ordering is derived, not agreed" property that T-03 established.
- **It is stable under its own output.** A window recomputes from `t` every update, so it
  re-derives the unadjusted note and re-applies the rule rather than compounding a previous
  adjustment. The peer sees the *adjusted* hz, finds no tritone, and stays put. There is no
  feedback loop, and a unit test sweeps every tenor degree against every alto note to prove the
  duet is never left a tritone from either side.
- **`hzToMidi` rounds.** Peers broadcast frequencies, not note numbers, so the rule has to get
  back to semitones. A unit test round-trips every note in the piece through
  `midiToHz`/`hzToMidi` to pin that the rounding never lands a semitone out.
- **Only voices with `hz > 0` count as "other".** A listener is in the roster but not in the
  chord, so it must not make a duet look like a trio and switch the rule off.
- **Two different departure budgets in the e2e suite, and they are not interchangeable.**
  A close is instant because of the `bye`, so `DEPART` is 3500 ms. A **prune** is 3000 ms of
  silence *plus* up to one 500 ms beat before anybody looks — it needs 5000 ms. The first version
  of the prune test used `DEPART` and failed on the boundary. If a future task tightens either
  number, tighten the right one.
- **Reaching the prune path in a test means patching `BroadcastChannel.prototype.postMessage` to
  a no-op** in the window that should disappear. Closing the page sends a `bye` and exercises the
  other path entirely. No production code was added for this.
- **Dragging is simulated by redefining `window.screenX`.** Playwright cannot move a window, but
  the frame loop only reads that property, so overriding it exercises the real path. The glide
  test asserts `voiceCount` stays 1 and `oscillatorCount` stays 4 while the pitch moves — proof
  the voice glided rather than being rebuilt.

## Deliberately left

- **The `<pre>` dump is still the UI.** **T-08** replaces it with the canvas and buys back ~15
  code lines.
- **`avoidTritone` still only applies to a duet**, per the brief. Three or more voices rely on
  the shared scale alone, which is correct: the rule exists because a two-note chord has nothing
  to hide a tritone behind.
- **No test asserts the absence of clicks.** It is the one thing in this task that is genuinely
  only audible. The `.value =` discipline test from T-06 is the structural proxy; a human should
  still listen at this milestone.
